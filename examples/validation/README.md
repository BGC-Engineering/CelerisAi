# Celeris validation

One CLI, one data root, every case reproducible on another machine.

```bash
# help
uv run python examples/validation/cli.py --help

# cases (figures + metrics land in <case>/results/, tracked in git)
uv run python examples/validation/cli.py run dambreak               # Stoker + Ritter, exact, CPU
uv run python examples/validation/cli.py run bump                   # exact flow over a crest, both inflows
uv run python examples/validation/cli.py run breach --inflow boundary
uv run python examples/validation/cli.py run malpasset
uv run python examples/validation/cli.py run all                    # everything + regression checks

# regression baselines (Tracy Arm, 4 coastal examples, breach, Malpasset)
uv run python examples/validation/cli.py regress check --tag conserving_v2 --wetdry conserving
uv run python examples/validation/cli.py regress compare legacy_det conserving_v2 --tol 1e-3
uv run python examples/validation/cli.py regress plot legacy_v2 conserving_v2
uv run python examples/validation/cli.py regress freeze --tag <new_tag> --wetdry conserving

# data: everything large lives under the data root, not in git
export CELERIS_VALIDATION_DATA=/path/to/root          # default /mnt/d/Homathko/Validation
uv run python examples/validation/cli.py data pack     # -> <root>/pack/celeris_validation.tar (one file to upload) + the archives and manifest
uv run python examples/validation/cli.py data fetch "https://sadsdev.blob.core.windows.net/celeris/celeris_validation.tar?<sas>"   # ask the project lead for a read SAS
uv run python examples/validation/cli.py data verify
```

## Data root layout (`paths.py`)

| path | content | size |
|---|---|---|
| `telemac/` | TELEMAC-2D reference runs as npz + csv + cas + listings | ~0.8 GB |
| `telemac_examples/` | the TELEMAC example inputs the cases read (meshes, cli, `analytic_sol.py`); used when no TELEMAC install exists | ~5 MB |
| `celeris/` | Celeris case outputs (grids, results, frames); regenerated by `run` | ~0.8 GB |
| `baseline/<tag>/` | regression baselines: `fields.npz` + `metrics.json` per case | ~70 MB per tag |

`data pack` copies the needed TELEMAC example files into `telemac_examples/`,
writes three archives (`telemac_examples`, `telemac_ref`, `baselines`) with a
sha256 manifest, and bundles them into one `celeris_validation.tar` (~0.9 GB).
`data fetch` takes either that single bundle (URL with SAS token, or a local
path) or a base URL holding the manifest and archives; it verifies and extracts. Tags in the baselines archive: `legacy_det` and
`conserving3` (before the discharge boundary), `legacy_v2` and `conserving_v2`
(current code). Regression `check` compares at 1e-6 m, i.e. bitwise on the
deterministic solver.

## Cases

| folder | what | reference |
|---|---|---|
| `dambreak/` | Stoker (wet) and Ritter (dry) dam breaks | exact, TELEMAC HLLC |
| `bump/` | steady flow over a bump, discharge boundary and interior source | exact, TELEMAC HLLC twins |
| `breach/` | TELEMAC breach channel, dyke intact: hydrograph routing and overtopping | TELEMAC-2D |
| `malpasset/` | 1959 dam break | lab gauges, transformer times, TELEMAC HLLC |
| `regression/` | 8-case freeze/check/compare/plot harness | frozen baselines |

Each folder's README carries the setup, the numbers and what was learned.
